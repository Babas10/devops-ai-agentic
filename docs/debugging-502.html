Conclusion: The 502 on qwen was caused by Knative state corruption (stuck in Proxy mode) from manual InferenceService patches during the GPU deadlock. The fix is to recreate qwen cleanly.

Root Cause

The 502 was not a networking misconfiguration, mTLS issue, or application bug. It was a Knative autoscaler state corruption caused by repeated manual patches to the InferenceService (minReplicas=0 → minReplicas=1) made during the GPU scheduling deadlock resolution. Each patch created a new Knative Revision (00002 → 00006), and the Knative autoscaler's ServerlessService got stuck in mode: Proxy with numActivators: 4. In Proxy mode all external traffic flows through the Knative activator, but the activator was in a stale state where it accepted TCP connections yet never forwarded HTTP requests to the pod. The pod itself (vLLM on /mnt/models) was fully healthy throughout. The fix: delete and recreate the InferenceService cleanly using the standard RHOAI vllm-cuda-runtime template.
